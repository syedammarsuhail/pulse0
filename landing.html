How it works

Three steps to complete observability

No infrastructure to provision. No configuration files to write.

Deploy Pulse0

Run a single Docker command, apply a Helm chart, or download the binary. Starts in seconds with zero config.

Point your OTLP endpoint

Set OTEL_EXPORTER_OTLP_ENDPOINT to your Pulse0 instance. Any OpenTelemetry SDK or Collector works out of the box.

See everything

Traces, logs, metrics, service map, and Live Insights appear immediately. Create dashboards, SLOs, and alerts from the UI.

Get started

Deploy in under five minutes

Every deployment starts as Community (free). Add a license key to unlock Pro.

# Run Pulse0 with persistent storage
docker run -d --name pulse0 \
  -p 4318:4318 \
  -v pulse0-data:/data \
  pulse0/pulse0:latest

# Upgrade to Pro: add your license key
docker run -d --name pulse0 \
  -p 4318:4318 \
  -v pulse0-data:/data \
  -e PULSE0_LICENSE_KEY=PULSE0-XXXX-XXXX-XXXX-XXXXXXXX \
  pulse0/pulse0:latest

Data persists in the pulse0-data volume. The UI and OTLP endpoint share port 4318.

# Add the Helm repo and install (Community)
helm repo add pulse0 https://charts.pulse0.dev
helm repo update
helm install pulse0 pulse0/pulse0 \
  --namespace observability \
  --create-namespace \
  --set auth.token=YOUR_TOKEN

# Upgrade to Pro: set your license key
helm upgrade pulse0 pulse0/pulse0 \
  --set license.key=PULSE0-XXXX-XXXX-XXXX-XXXXXXXX
# Download and start
curl -O https://get.pulse0.dev/docker-compose.yml
docker compose up -d

# To activate Pro, add to .env:
PULSE0_LICENSE_KEY=PULSE0-XXXX-XXXX-XXXX-XXXXXXXX
# Download and run directly
pip install -r requirements.txt
python server.py

# Pro: set the env var before starting
export PULSE0_LICENSE_KEY=PULSE0-XXXX-XXXX-XXXX-XXXXXXXX
python server.py

Then connect your application

# Set these env vars on any OpenTelemetry-instrumented service
OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318
OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf

# Open http://localhost:4318 to see your data.

FAQ

Common questions

What's the difference between Community and Pro?
Community monitors up to 5 services with 7-day retention, 3 dashboards, 3 alerts, and 1 SLO. It's real observability, not a trial. Pro removes every limit and adds SSO, RBAC, audit logging, the AI assistant, and Postgres support. Both are self-hosted and run the same binary.
Why $490/year?
At $490 you're under most companies' $500 procurement threshold, so engineers can approve it without a purchasing process. It's flat: no per-host fees, no per-seat charges, no usage meters. One key covers your whole team.
Can I try Pro before buying?
Deploy Community and use it with real data. When you hit a limit (6th service, 4th dashboard, need SSO), you'll see exactly what Pro unlocks. Buy a key and set it in your environment to upgrade instantly with no data loss.
What's a BSL license?
Business Source License means the code is visible and you can use it freely, but you cannot resell it or offer it as a hosted service competing with Pulse0. After four years, each version converts to Apache 2.0.
How much traffic can it handle?
A single instance handles around 2,500 spans/second on a 2-vCPU machine. For most teams with up to 50 services, that's more than enough. The Cloud tier will add horizontal scaling.
Is it OpenTelemetry compatible?
Native OTLP HTTP on port 4318. Any OpenTelemetry SDK or Collector can send traces, logs, and metrics directly. Supports both JSON and Protobuf encoding.
Can I use my own Postgres?
On Pro, set PULSE0_DATABASE_URL to any Postgres connection string. Community uses SQLite only. Both backends support the same features.
What happens to my data?
Your data stays on your infrastructure, always. Community and Pro are self-hosted. Data never leaves your network and there's no phone-home.
